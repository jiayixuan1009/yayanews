# Loop Engine Production Runbook

Date: 2026-06-26

## Purpose

Enable the Loop Engine as a safe daily feedback loop for
`https://yayanews.cryptooptiontool.com/`.

The loop may import GSC, GA4, crawl-log, or other feedback signals, score
opportunities, queue low-risk actions, and write reports. It must not deploy,
publish edited article text, change canonical/noindex/redirect behavior, or
modify Nginx.

## GSC Credentials

Preferred credential path:

```bash
export GOOGLE_APPLICATION_CREDENTIALS=/var/www/yayanews/secrets/gsc-service-account.json
```

The service account must have read access to the exact GSC property:

```text
https://yayanews.cryptooptiontool.com/
```

Supported alternatives:

- `GSC_SERVICE_ACCOUNT_JSON`: full service-account JSON as an environment value.
- `GSC_OAUTH_TOKEN_FILE`: OAuth token JSON generated by a prior authorized
  setup. Use only when its Google account has Search Console access.
- `GSC_OAUTH_TOKEN_JSON`: full OAuth token JSON as an environment value.
- `GSC_ACCESS_TOKEN`: a short-lived token with
  `https://www.googleapis.com/auth/webmasters.readonly`.
- `GSC_IMPERSONATE_SUBJECT`: optional Google Workspace domain-wide delegation
  subject, only if the account is configured for it.

Never commit credential JSON or tokens.

If only a parent Domain property is available, configure the Domain property and
filter imports to the YayaNews subdomain:

```bash
export GSC_SITE_URL=sc-domain:cryptooptiontool.com
export GSC_PAGE_FILTER_PREFIX=https://yayanews.cryptooptiontool.com/
```

Local verification is fixed through:

```bash
npm run verify:google-apis
```

If the local default Node is still outside the repo range, use the direct
script form until switching to Node `20.19.x`:

```bash
node scripts/verify/google-api-connections.mjs
```

## Daily Command

Use a completed GSC data window. GSC performance data can lag, so a safe daily
schedule is usually yesterday or two days ago.

```bash
npm run loop:gsc -- \
  --date-start 2026-06-19 \
  --date-end 2026-06-25 \
  --limit 300
```

This command:

1. Fetches Pages and Queries through the Search Console API.
2. Writes CSV exports to `outputs/gsc-performance/gsc-YYYY-MM-DD/`.
3. Imports the CSV data into `seo_feedback_snapshots`.
4. Scores `content_opportunities`.
5. Executes only low-risk `loop_actions`.
6. Writes a Markdown report under `outputs/loop/`.

If API credentials are not available, use file-based mode:

```bash
npm run loop:latest -- \
  --date-start 2026-06-19 \
  --date-end 2026-06-25
```

## Cron Example

Example only. Adjust dates through a wrapper script so the window is always
explicit.

```cron
15 4 * * * cd /var/www/yayanews && /usr/bin/npm run loop:gsc -- --date-start $(date -u -d "8 days ago" +\%F) --date-end $(date -u -d "2 days ago" +\%F) --limit 300 >> outputs/loop/cron.log 2>&1
```

If shell date portability is uncertain, prefer a small wrapper script that
prints exact dates before running.

## Post-Run Checks

Run these after the first production execution:

```bash
npm run loop:report -- --output outputs/loop/loop-report-post-run.md
npm run ops:public-health
npm run verify:seo
npm run verify:redirects
```

Check:

- `loop_runs.status = completed` for import, score, execute.
- `loop_actions` only contains expected low-risk action types.
- No published article fields changed unless another explicit publishing job
  was run.
- Agent 6 can see queued `translate_en_priority` actions.

## Rollback

Loop Engine writes are isolated to:

- `loop_runs`
- `seo_feedback_snapshots`
- `content_opportunities`
- `loop_actions`
- `loop_action_results`
- `loop_feedback_events`

If a bad import batch is detected, dismiss or delete only that batch after
recording the batch key and run IDs. Do not delete articles as a Loop rollback.

## Known Local Build Note

On the Windows desktop workspace, PM2 can keep `apps/admin/.next/standalone`
open while `yaya-admin` is running. Local `npm run build:admin` therefore uses
`.next-validation` without standalone output. Production standalone builds use:

```bash
npm run build:admin:standalone
```
