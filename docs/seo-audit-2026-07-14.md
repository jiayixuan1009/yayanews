`https://yayanews.cryptooptiontool.com/` is currently reachable, crawlable, and
indexable. The current organic-growth problem is not a broken GA4 tag, a missing
sitemap, or a whole-site Google block.

## DNS Is Not Web Traffic

The Cloudflare screenshot reports DNS queries, not HTTP page loads or unique
visitors. YayaNews had about `38.76k` DNS queries in the shown 24-hour window:

- A queries: approximately `22.23k`
- AAAA queries: approximately `16.35k`
- Current DNS TTL: approximately `300` seconds
- Returned addresses: Cloudflare anycast edge addresses

Resolvers, scanners, monitors, crawlers, and browsers can query both A and AAAA.
Resolver caches can refresh independently every TTL window. Cloudflare DNS data
center geography is where the authoritative query was handled, not a reliable
end-user location. DNS query counts therefore cannot be converted into visits.

## Changes Implemented Locally

### Cloudflare / Nginx observability

- Added all current official Cloudflare IPv4 and IPv6 proxy ranges as trusted
  `set_real_ip_from` sources.
- Added `real_ip_header CF-Connecting-IP` and `real_ip_recursive on`.
- Changed upstream `X-Forwarded-For` to the restored `$remote_addr`, avoiding a
  duplicated client address after real-IP restoration.
- Added a dedicated JSON-escaped access log:
  `/var/log/nginx/yayanews.access.log`.
- Log fields include visitor IP, method, normalized path without query string,
  status, response bytes, request time, referrer, UA, CF-Ray, and retained
  Cloudflare edge address.
- Existing API/admin rate limits now use the restored visitor address through
  `$binary_remote_addr`.
- Kept `infra/nginx/yayanews.conf` and
  `infra/deploy/nginx-yayanews.conf` byte-identical.

Verification and operations:

- `scripts/verify/cloudflare-real-ip-config.mjs` checks both local configs
  against Cloudflare's current official IP lists and detects config drift.
- `infra/scripts/install-yayanews-nginx.sh` installs with backup, `nginx -t`,
  reload, and automatic rollback on failure.
- `scripts/verify/analyze-nginx-traffic.mjs` analyzes plain or gzipped access
  logs by IP, UA, path, status, referrer, response time, and Cloudflare colo.

Official sources:

- `https://www.cloudflare.com/ips-v4`
- `https://www.cloudflare.com/ips-v6`
- `https://developers.cloudflare.com/support/troubleshooting/restoring-visitor-ips/restoring-original-visitor-ips/`

## Deployment And Rollback

Do not copy the Nginx file directly without validation. On production:

```bash
cd /var/www/yayanews
node scripts/verify/cloudflare-real-ip-config.mjs
sudo bash infra/scripts/install-yayanews-nginx.sh
```

The installer writes a timestamped backup under
`/var/backups/yayanews-nginx/`. It restores the previous file and reloads Nginx
if syntax validation or reload fails.

After deployment:

```bash
sudo tail -f /var/log/nginx/yayanews.access.log
sudo node scripts/verify/analyze-nginx-traffic.mjs /var/log/nginx/yayanews.access.log --limit 30
```
