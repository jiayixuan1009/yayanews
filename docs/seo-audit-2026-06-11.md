# YayaNews SEO 审计报告

审计日期：2026-06-11  
审计对象：`https://yayanews.cryptooptiontool.com`  
审计范围：技术 SEO、页面 SEO、Google News SEO、多语言 SEO、结构化数据、抓取与索引、基础性能与安全头。

## 1. 执行摘要

YayaNews 当前 SEO 基础较完整。核心页面可访问，`robots.txt`、普通 sitemap、Google News sitemap、RSS、文章页结构化数据、首页组织结构化数据均已上线并可抓取。整体不是从零补 SEO 的状态，而是需要修复几个会影响英文页面收录和页面信号一致性的关键问题。

最高优先级问题是英文栏目页 canonical 错误。线上 `/en/news/us-stock`、`/en/news/crypto`、`/en/news/hk-stock`、`/en/news/derivatives` 的 canonical 和 `og:url` 均指向对应中文页，且 `og:locale` 输出为 `zh_CN`。这会让搜索引擎把英文栏目页合并到中文 canonical，削弱英文页独立收录。

第二个重点是部分静态政策页使用旧式静态 metadata，canonical 没有语言前缀，例如 `/zh/privacy` 输出 canonical 为 `/privacy`。此外，Next.js 会将部分 metadata 流式注入到 body 后部，Googlebot 通常可以识别，但对低能力爬虫和部分 SEO 工具存在兼容风险。

## 2. 关键发现

### P0 - 英文栏目页 canonical 指向中文页

影响页面：

- `https://yayanews.cryptooptiontool.com/en/news/us-stock`
- `https://yayanews.cryptooptiontool.com/en/news/crypto`
- `https://yayanews.cryptooptiontool.com/en/news/hk-stock`
- `https://yayanews.cryptooptiontool.com/en/news/derivatives`

线上证据：

| 页面 | 实际 canonical | 实际 `og:locale` |
| --- | --- | --- |
| `/en/news/us-stock` | `/zh/news/us-stock` | `zh_CN` |
| `/en/news/crypto` | `/zh/news/crypto` | `zh_CN` |
| `/en/news/hk-stock` | `/zh/news/hk-stock` | `zh_CN` |
| `/en/news/derivatives` | `/zh/news/derivatives` | `zh_CN` |

代码位置：

- `apps/web/src/app/[lang]/news/[category]/page.tsx`

根因：

`generateMetadata` 调用 `createMetadata` 时没有传入 `lang`，导致 `createMetadata` 默认按中文生成 canonical、Open Graph locale 和 URL。

建议修复：

```ts
return createMetadata({
  title: meta.title,
  description: meta.desc,
  url: `/news/${category}`,
  lang: lang === 'en' ? 'en' : 'zh',
});
```

同时建议保留 `url: /news/${category}`，不要传入 `/${lang}/news/${category}`，因为 `createMetadata` 内部已经会加语言前缀。

### P1 - 部分政策页 canonical 不本地化

影响页面：

- `/zh/privacy`
- `/en/privacy`
- `/zh/contact`
- `/en/contact`

代码位置：

- `apps/web/src/app/[lang]/privacy/page.tsx`
- `apps/web/src/app/[lang]/contact/page.tsx`

当前代码使用：

```ts
alternates: { canonical: '/privacy' }
```

以及：

```ts
alternates: { canonical: '/contact' }
```

问题：

这些页面位于 `[lang]` 路由下，但 canonical 没有包含 `/zh` 或 `/en`。这会造成 canonical 指向无语言路径，而无语言路径又会被 middleware 重定向到语言路径，信号不够干净。

建议修复：

将静态 `metadata` 改为 `generateMetadata`，统一使用 `createMetadata`：

```ts
export async function generateMetadata({
  params,
}: {
  params: Promise<{ lang: string }>;
}): Promise<Metadata> {
  const { lang } = await params;
  const locale = lang === 'en' ? 'en' : 'zh';

  return createMetadata({
    title: locale === 'en' ? 'Privacy Policy' : '隐私政策',
    description: locale === 'en'
      ? 'YayaNews privacy policy and user data practices.'
      : 'YayaNews 隐私政策与用户数据说明。',
    url: '/privacy',
    lang: locale,
  });
}
```

### P1 - SSR HTML 默认返回 `private, no-cache, no-store`

线上抽样：

- `/zh`
- `/en`
- `/zh/news`
- `/zh/news/us-stock`
- `/zh/article/...`
- `/zh/topics`

均返回：

```http
Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate
```

影响：

新闻站需要新鲜度，但全站 HTML 都 `no-store` 会增加源站压力，影响 TTFB 稳定性，也降低 CDN 缓存价值。对 Googlebot 来说，页面可抓取，但抓取成本更高。

建议：

- 首页：保留短缓存或 60 秒 ISR。
- 新闻列表、栏目页：建议 `s-maxage=60` 到 `300`。
- 专题、作者、政策页：建议 `s-maxage=300` 到 `86400`。
- API 和管理后台继续 `no-store`。

### P2 - 部分 metadata 通过 Next.js 流式注入到 body

复核页面：

- `/zh/privacy`
- `/zh/contact`
- `/zh/terms`
- `/zh/risk-disclosure`

发现：

`<title>`、description、robots、canonical 确实存在，但部分位置出现在 `</head>` 后、`<body>` 内的流式补丁脚本之后。

说明：

Googlebot 通常可以识别 Next.js App Router 的流式 metadata，但某些 SEO 抓取工具、社交抓取器或低能力爬虫可能只读取初始 `<head>`，从而误判这些页面缺少 title/canonical。

建议：

对重要落地页、政策页、栏目页尽量使用同步可解析的 metadata 生成路径，避免过多依赖流式 metadata。优先修复 `privacy` 和 `contact`，并观察构建后 metadata 是否进入初始 head。

## 4. 页面 SEO 观察

### Title

整体 title 覆盖较完整。抽样：

- `/zh`：`鸭鸭财经新闻 今日财经资讯 · 美股、港股、加密货币实时新闻`

- `/zh/news`：`金融新闻深度分析 | 美股·港股·加密货币·衍生品 | 鸭鸭财经新闻`
- `/en/news`：`Financial News & In-Depth Analysis | US Stocks, Crypto, HK Markets | YayaNews`

建议：

`/en/news` title 长度约 77 字符，略长。建议压缩到 55 到 65 字符，例如：

```txt
Financial News & Market Analysis | YayaNews
```

### Description

中文核心页 description 质量较好。英文 `/en/news` description 约 197 字符，偏长，搜索结果中可能被截断。

建议：

将英文核心页 description 控制到 140 到 160 字符附近。

### H1

核心页面均有 1 个 H1。首页 H1 来自首屏主文章标题，新闻门户常见且可接受。

### OG 图

当前默认 OG 图：

```txt
/brand/logo-square.png
```

问题：

默认图为方形 logo，但 metadata 中声明为 1200x630。社交分享和部分搜索预览更适合横版图。

建议：

新增 1200x630 的默认 OG 图，并将 `DEFAULT_OG_IMAGE` 改为横版路径，例如：

```ts
const DEFAULT_OG_IMAGE = '/brand/og-default.png';
```

## 5. 多语言 SEO

### 已做好的部分

- `/zh` 和 `/en` 均有互相 alternate。
- 普通 sitemap 中静态页、栏目页、专题页、标签页都有 `xhtml:link` alternate。
- 文章页只在存在 sibling 翻译时输出成对 hreflang，避免伪造 404 英文页，这个策略是正确的。

### 需要修复的部分

英文栏目页 canonical 错误是当前最关键问题。修复后应重新验证：

- canonical 指向自身英文 URL。
- `og:url` 指向自身英文 URL。
- `og:locale` 为 `en_US`。
- alternate 中同时保留 `zh` 和 `en`。

## 7. 性能与可用性

PageSpeed Insights API 当前返回 429：

```txt
Quota exceeded for quota metric 'Queries' and limit 'Queries per day'
```

因此本轮未能取得 Lighthouse 分数。

代码侧观察：

- `_next/static` 静态资源配置了长期 immutable 缓存。
- sitemap、News sitemap、RSS 设置了合理缓存。
- GA 使用 `lazyOnload`。

主要风险：

- 新闻首页首屏图片和实时组件可能影响 LCP，需要后续用 Lighthouse 复测。
